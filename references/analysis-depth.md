# 分析深度与阅读产物

用户要求详细解读、认为大纲过短或需要分段内容时，使用这份补充说明。脑图是导航，不能替代解释。

## 内容质量

从材料中识别论点、论据、推理步骤、例子、限定和前后衔接，选择对理解有帮助的内容写入节点正文；不要求每个节点机械套齐栏目。明显有多个推理环节时，保留过程，不只写最终结论。概念密集的材料要说明容易混淆的区别。语音口误、作者简化与整理者补充分别标明。

按内容决定层级和长度，避免把材料压缩成固定条目数，也不要为了显得详细而添加材料没有支持的解释。完整阅读范围和解释深度是不同的质量维度，均应核对。

## 数据格式

保留已有 title、children、body、evidence；body 可用空行分隔多个段落。增补字段：

```json
{
  "title": "材料主题",
  "notice": "真实覆盖范围；内容属于分析还是原文。",
  "summary": "帮助理解全片的问题线索。",
  "children": [
    {"title": "主题", "body": "结论与推理。\n\n例子和限定。",
     "evidence": ["实际转写ID"]}
  ],
  "timeline": [
    {"start": 0, "end": 75, "title": "这段讨论的问题",
     "body": "用自己的话概括这段的推进，不复制原文。",
     "evidence": ["范围内的实际转写ID"]}
  ],
  "review": "识别勘误、概念限定和补充来源，按空行分段。"
}
```

timeline 按语义转折划分，不必机械按等长时间切割。每段要有真实引用和非空正文；时间有限、递增、不重叠、不超出素材时长，引用的证据必须与该范围相交。声明完整覆盖时，另核对没有漏段，特别是开头、广告和结尾；验证器不会自动证明内容涵盖完整。

render / finish 会生成 reading.html，保留详细正文并提供检索；有 timeline 时生成 segments.md，有 review 时生成 review.md。FreeMind 正文进入节点备注；脑图仍保留完整树。重渲染取消可选字段时移除旧的对应文件，finish 后已有 ZIP 失效，需重新 bundle。

## 原始分段与释义的区别

work/transcript.json/.txt/.srt 已保存机器识别的时间段，不等于作者书面原稿或人工校勘稿。时间释义来自内容分析，不能把它命名为原文。完整逐字交付按用户材料权限和适用内容规则判断；仅给外部链接时不把完整受保护内容转存为交付文件。通用导出默认不复制原始转写，交付包也不包含它。
